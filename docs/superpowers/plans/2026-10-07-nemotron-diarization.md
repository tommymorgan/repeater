# Local transcription, speaker diarization and overlap recovery for The Repeater

Status: implemented and real-model integration verified on 2026-10-07. Tommy authorized both native Multitalker Parakeet and coupled Nemotron 3.5 + diarization, including isolated installation/model downloads and public/synthetic inference. Model selection is manual, based on anticipated attendance. Existing private recordings/preferences, capture devices and running applications remained outside verification scope. Current proof and quality limits are in docs/linux-port.md; the source research below is the historical selection evidence, not a quality promise.

## Direction and priority order

Tommy reports that more than four attendees is common and more than eight is possible in his largest meetings. The selected implementation has two profiles: native four-slot Multitalker Parakeet and coupled eight-slot Nemotron 3.5 + V3 diarization. Neither supports more than eight voices per mixed source. Manual switching does not solve that capacity limit. Priorities remain:

1. Something that works as soon as possible.
2. Highest practical quality.
3. Operation on modest hardware.

He strongly favors recovering **both people's words during simultaneous speech**, citing Google Meet. This is a quality/model-selection criterion, not merely detecting two active speakers. Do not promise perfect recovery or Google Meet parity. Keep inference local; no cloud service, Meet-specific capture integration, biometric voice profiles or Android implementation is included.

The built native Parakeet provider is independently pinned transcribe.cpp 0.2.3 / 63a44d92 with the checksum-verified Q8 overlap-trained bundle; the permanent binary does not depend on Handy. The coupled Nemotron provider is pinned NeMo Speech / 50c71dbe with Nemotron 3.5 ASR and eight-slot V3 diarization, masked per-speaker parallel ASR, and genuine RNNT token-derived word times. Both receive each whole source independently; no external chunking resets speaker identities.

Fresh preferences and CLI default to Nemotron 3.5; the GTK selector saves separate paths for both profiles. Legacy Whisper settings remain unselected until an explicit choice. New canonical schema v2 stores opaque generation and source-scoped speaker UUIDs, neutral labels, independent acoustic speakerTurns, immutable Me/Them source and genuine optional Unicode word spans. Complete-generation Undo preserves old v1 transcripts and their original exports. Microsoft candidates remain research comparisons, not implemented fallback engines. Final proof and limits belong in docs/linux-port.md.

### Microsoft distinctions that affect selection

- VibeVoice-TTS / VibeVoice-Realtime and MAI-Voice are speech generation, not this transcription task. Do not import TTS's four-speaker or 90-minute generation promises into ASR. The July BitNet and September streaming ASR releases are relevant recent Microsoft announcements; which announcement Tommy recalls is not established.
- Full VibeVoice report `4 says it does not handle overlap explicitly and tends to miss secondary information. Streaming report `3.2 targets overlapped lexical training, but `6 limits sustained overlap and Appendix A emits no timestamps. Its UI estimates must not enter canonical word-excerpt data.
- Missing decoder times are an integration cost, not automatic disqualification. Qwen3-ForcedAligner-0.6B is a real audio-plus-text aligner (English among eleven languages, up to five-minute inputs). Validate acoustic boundaries, each recovered simultaneous voice, crop/global offsets, Unicode units and seams. Never concatenate simultaneous voices into one monotonic alignment or uniformly spread sentence/chunk times. Alignment cannot recover speech the recognizer omitted.
- BitNet's native default is 16,384 context tokens; a 70-minute 24 kHz input implies about 31,500 audio prompt tokens before text/output. The pinned VAE arena formula is `n_samples * 10240 + 512 MiB`; [INFERENCE] whole-file 70 minutes requests about 961.8 GiB of arena, not measured RSS. Bounded chunks still lack recording-wide speaker/time reconciliation. Do not interpret ~1.58 GiB weights as total memory.
- Full/streaming 7B checkpoints contain about 17.35 GB of tensor payload, not measured loaded RAM/VRAM; framework, activations and retained context add memory. Full custom-repo Transformers <5 and the official HF conversion's Transformers >=5.3 are different environment lanes. Public A100/server benchmarks do not establish this workstation's throughput or mobile feasibility. Hardware is third priority, but missing functional contracts still matter first.

## First deliverable: one complete local desktop path

### 1. Prove and select the runtime, before changing saved transcripts

After explicit build/download authorization, isolate environments and use public/synthetic audio only. Resolve immutable models to explicit local paths; no implicit defaults or hidden downloads in the shipped command. Start with multitalker Parakeet's native **bundle**, not the plain ASR artifact, when the four-slot cap fits. Its documented future file command is `transcribe-cli --diarize -m <pinned-bundle.gguf> <public.wav>`; check the actual binary's help and supported feature/ABI first, and obtain real word/segment/speaker data through the concrete CLI or C API. The installed library is not proof a CLI is installed. Keep default cache-aware kernel mode; never enable `TRANSCRIBE_MULTITALKER_OFFLINE=1` for hour-long audio, because that replay allocates quadratic attention buffers.

For five through eight voices in one mix, use the official NeMo multitalker Parakeet + V3 example with `masked_asr=false`, `parallel_speaker_strategy=true`, `cache_gating=true` and `max_num_of_spks=8`; freeze versions and prove parallel word export. Nemotron 3.5 comparison uses masked ASR instead. The native English/V3 baseline's future shape is `nemo-speech transcribe <public.wav> --model <vendor-english.gguf> --diar-model <vendor-v3.gguf> --backend cpu --json`. Verify actual flags; no recipe was run in this planning session. Word attribution and acoustic activity should come from one inference session, or require a proved ID mapping across independent runs.

Use three independent checks:

- **Recognition and timing:** known text/pauses/silence, Unicode and late speech; decoder-derived word timing or independently validated real acoustic alignment; positive intervals within unpadded audio, declared provenance, no invented uniform spacing. Convert byte/token coordinates to Unicode-character spans. Sentence timing alone is not word alignment. Prove any additional exporter/aligner and count its runtime/integration cost before selecting the route.
- **Speaker continuity and capacity:** alternate voices across chunk seams and long silence; three/four voices for the native bundle, plus five/eight for V3; stable source-scoped recording/generation identities. Fixed slots may merge excess people without detecting overflow. Test fifth/ninth respectively, document the limitation, and reject known declared counts beyond the cap; do not promise automatic overflow detection or unrestricted capacity.
- **Overlap recall:** mix two voices saying different known phrases with per-voice references, non-overlap controls, unequal volumes and sustained double-talk. Score each voice's omissions, substitutions/insertions, attribution and timestamp error. Two active slots or duplicate copies of one hypothesis are not recovery. No numeric threshold or Google Meet benchmark has been accepted; report results and tradeoffs, not an invented pass score.

Choose one runtime for first integration on that evidence. Favor the existing overlap-trained path if it passes word/speaker/long-recording gates; Microsoft streaming plus an aligner remains a valid comparison if a complete 70-minute route becomes demonstrable. If only ordinary attribution works first, disclose the overlap limitation rather than silently redefining the desired feature. No automatic engine/model fallbacks and no generic plugin system.

### 2. Introduce the smallest data contract that separates people from sources

Implement a versioned transcript schema, proposed version **2**, in `linux/transcribe.py`. Keep the session manifest and aligned 16 kHz mono PCM16 `mic.wav`/`system.wav` files unchanged. Preserve existing `source: me|them` values as capture-lane keys; Me/Them are not individual speaker identities.

- Keep canonical segments/text/absolute times and validated Unicode-character word spans. Add a speaker registry scoped to a generated result, opaque source-scoped speaker IDs, stable display ordering and exact ASR/diarizer provenance/status/capacity. No biometric identity or automatic real names. Independent lanes' slot 1 values must not be treated as the same person; mic can contain multiple local voices or echo.
- Word attribution is a single recognized speaker ID where supported, or an explicit unknown/unavailable state with no fake Speaker 0. Record whether it came from coupled per-speaker ASR or native post-hoc word tags. Keep concurrent **speaker activity turns** separate from word attribution; a word occurring during two active voices must not be assigned to both by assumption. Preserve true parallel recovered words as separate speaker segments with overlapping times. Activity timing resolution is not word-boundary accuracy.
- Form speaker turns from actual aligned words while retaining every decoded text character and recalculating spans. Preserve uncertainty at gaps/ties rather than applying unlimited nearest-speaker matching. Untimed/mixed segments remain honestly untimed/mixed; no fabricated word identity. Neutral Speaker 1/2 labels are a proposed initial display, ordered by first appearance and stable over reopen. New retranscription creates a new speaker namespace; same ordinal does not establish the same human across runs or recordings.
- Continue reading schema 1 and its history without mutation on open, label it source-only/individual attribution unavailable, and invent no speaker registry from Me/Them. Only an explicit successful retranscription publishes schema 2. Undo must restore the complete old version; no wholesale migration of the recording archive.

Keep one canonical JSON authority; do not create a second authoritative diarization database/sidecar. Acoustic turns and generated words survive text correction as original evidence. Editing text invalidates current word spans/word attribution when alignment no longer matches; display original segment speaker context as generated context, not acoustic attribution of newly typed words.

Diarization disabled must be a genuine ASR-only mode with attribution marked unavailable and no dependency on a missing diarizer artifact. Requested diarization failing must fail the new result and preserve the old exports/history; offer explicit retry or rerun without diarization rather than claiming detection succeeded. If the selected coupled runtime cannot provide the disabled mode directly, use its concrete supported single-speaker inference path with the same selected ASR checkpoint, not a stub.

Successful retranscription remains an undoable whole-payload replacement: it does **not** automatically transplant old text corrections onto newly recognized words. Warn about replacement of corrections/attribution before explicit reprocessing. Historical review findings remain retained but inactive for a different generated result; restoring an old generation can restore its findings under existing revision rules. Future display-name changes must not unnecessarily invalidate ASR/review generations.

### 4. Prove the complete deliverable on isolated data

Extend existing behavioral suites in `linux/test-transcribe.py`, `linux/test-review.py`, `linux/test-playback.py` and `linux/test-desktop.py`; follow their existing command/test conventions. Run those suites and the real selected inference command, then exercise the actual GTK surface with an isolated synthetic data/settings home, no audio-device capture and no private recordings.

First-release gates include:

- A synthetic/public **70-minute two-lane** recording with speech and speaker changes near the end: full late content, bounded absolute word/turn times, no padding artifacts/chunk duplicates/identity resets, stable reopen. Include silence/empty legitimate lanes. Short-fixture success is not long-meeting proof.
- Real Thread/Timeline speaker labels, overlapping recovered rows where supported, original-lane turn/word playback and exact review highlighting; Unicode text correction, replacement, Undo/Redo and restart preserve the right original timings and complete speaker registry.
- Failure in either lane or requested diarization, missing/incompatible model, incompatible language, stale edit/review race, handled publication failure and cancellation during inference/before publication preserve previous canonical exports/history and leave audio/manifest unchanged; owned process groups/locks release and explicit retry works. No silent partial publication.
- Record wall time per recorded minute, peak process-tree RAM, peak VRAM/backend, speaker count and artifact/version pins, alongside recognition/attribution/overlap results. No performance estimate is a measured result. A slower workstation success can satisfy first delivery without pretending it already works on modest hardware.

Existing `_publish_exports` stages files and uses per-file atomic rename plus caught-error rollback and deferred cancellation; it is **not** crash-proof multi-file atomic publication under SIGKILL/power loss. Preserve and test the handled-failure contract. Do not turn this model change into an unrelated storage-transaction rewrite or claim stronger guarantees.

## After the first working path

1. **Quality:** compare ordinary English meeting-style recognition with the currently liked English checkpoint; examine misattribution, rapid turns and each voice's overlap recall. Improve the selected proven path or present the explicit overlap-trained model tradeoff. Manual speaker naming/reassignment/merge/split is separate product scope, not an unapproved prerequisite.
2. **Modest hardware:** measure CPU-only feasibility, backend choice, concurrency, cache/window settings and quantization against the proved quality baseline. Avoid CPU-only or small-RAM promises until measured. Speaker-specific computation grows with speaker streams; model file size alone is not a deployment estimate.
3. **Android exploration:** only after a working local desktop reference, prove NDK/JNI/CPU or Vulkan build, mobile memory/thermals, word/speaker contract and platform capture/background permissions. Linux aarch64 and a C API are starting evidence, not a working Android build. Do not assume the NeMo/PyTorch workstation route can ship unchanged on a phone.
