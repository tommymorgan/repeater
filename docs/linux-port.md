# The Repeater — Linux desktop and CLI port

The Repeater is the Linux fork of Parrot, with a native Python/GTK desktop application and a CLI for explicit two-track recording and post-recording offline transcription. Both share PipeWire capture, manually selected Multitalker Parakeet or coupled Nemotron 3.5 + diarization, and local session files. The GUI does not run the original SwiftUI application. Linux never evaluates the macOS signing or Swift build commands.

## Prerequisites and setup

1. Use Python 3.10 or newer and a running PipeWire user session with its policy manager (normally WirePlumber). Capture requires `pw-dump` and `pw-record` on PATH; `pactl` supplies default-device selection through pipewire-pulse. Without `pactl`, select both device names explicitly. A usable microphone and output sink must appear in `make devices`.
2. Install development prerequisites through your distribution package manager: Git, CMake, a C/C++ toolchain, Make, curl, sha256sum, OpenSSL development files and OpenBLAS. Parakeet CUDA builds require an NVIDIA CUDA development toolkit and working driver; Vulkan builds require Vulkan development tools. Nemotron setup requires uv and ffmpeg and installs a pinned Python 3.13/NeMo/Torch environment under .build/linux, not into system Python. The GUI and playback need Python PyGObject, GTK 4, libadwaita 1.5 or newer, and GStreamer base/good plugins (Arch: python-gobject, gtk4, libadwaita, gstreamer, gst-plugins-base, gst-plugins-good). Setup does not install system packages.
3. Run make linux-setup to install both models (Parakeet CUDA by default), or choose make linux-setup PROFILE=multitalker-parakeet MODE=cpu, MODE=cuda or MODE=vulkan; make linux-setup PROFILE=nemotron-3.5 installs only the coupled NeMo runtime. Sources, checkpoints, hashes and licenses are pinned and retained under .build/linux. Network access is needed for setup, not recording or inference. BUILD_JOBS controls native build parallelism; PARAKEET_CUDA_ARCHITECTURES can select a CUDA architecture.
4. Run `make` for Python syntax and setup-shell sanity, and `make devices` to inspect stable device names. Neither starts recording. `make gui` opens the desktop application without recording. `make run` and bare `python3 linux/parrot.py` show CLI help only.

Fresh preferences and CLI default to nemotron-3.5 because meetings commonly exceed four remote voices. Defaults resolve relative to this checkout, not the current directory. Parakeet uses .build/linux/bin/parakeet-transcribe and .build/linux/models/parakeet-bundle.gguf; Nemotron uses .build/linux/nemotron-venv/bin/python and the ASR/diarization .nemo files in .build/linux/models/nemotron-3.5 and nemotron-diarization. Neither runtime depends on Handy. Parakeet supports four distinct voices per mixed source and English only. Nemotron supports eight slots and 32 explicit language locales; en aliases en-US. Neither supports more than eight speakers per mixed source, and switching does not remove that limit. These are model capacities, not guarantees of accurate identity or overlap recovery.

## Use the desktop application

```bash
make gui
# Register/update the launcher and logo without opening the application:
make install-desktop
```

`make gui` registers the user-local **The Repeater** launcher and the selected radio logo before opening the window. The launcher lives at `XDG_DATA_HOME/applications/local.TheRepeater.desktop`; its matching icon is installed at `XDG_DATA_HOME/icons/hicolor/512x512/apps/local.TheRepeater.png`. `linux/identity.py` owns the shared display name, local application ID and icon source. The local ID avoids claiming the upstream developer’s GitHub namespace. The icon is a 512px export of the selected subtle radio concept in `linux/assets/logo-concepts/subtle-radio.png`; the unselected trooper concept is retained for reference, not installed. The launcher points to the current checkout and Python interpreter, so keep the checkout in place. Installation refuses to overwrite an unrelated launcher or symlink. `make install-desktop` updates branding without launching. This is user-local desktop integration, not a standalone package or automatic updater.

The desktop entry uses the installed PNG’s absolute path as `Icon=` rather than a theme name. GNOME Shell’s long-lived theme resolver can retain a missing-icon result when a new hicolor directory is added during a session; a fresh GTK lookup does not prove the switcher can load it. The direct file icon bypasses that named-theme lookup. On GNOME 50, the Shell `St.IconTheme` loader reproduced the stale named-icon miss and decoded the launcher’s file icon at 64px and 128px. Verification does not require restarting GNOME or changing theme settings.

The checkout path, CLI script paths, existing `parrot/meetings` storage and `parrot/settings.json` preferences are unchanged by this display-branding change. No recordings or settings are moved, copied or deleted. Upstream macOS source/artwork and attribution remain intact.

1. Enter a meeting title and choose the microphone and system audio output carrying the call. Both dropdowns offer **System default**, which stores no fixed device name and resolves the current system default when recording starts. Explicit choices save stable names; unavailable saved names remain visible rather than silently changing. Refresh audio devices after hardware or default-device changes. Without `pactl` or a usable default, choose explicit devices.
2. Open Settings from the header gear and choose Model manually: Multitalker Parakeet or Nemotron 3.5 + diarization. The selected model's capacity stays visible, and its checkpoint/runtime paths are saved separately so switching preserves both configurations. Choose a language locale, CPU threads and Use GPU. Valid edits autosave; Back and idle close flush recent valid edits. Invalid drafts keep the last saved preferences, show an inline error and block jobs. Native Back returns to the recorder or selected meeting. GPU is enabled by default; turn it off for CPU inference. Existing Whisper settings preserve device/review/common options but require an explicit model choice; loading them never rewrites the file or reuses old Whisper artifacts as new models. Old auto/short language codes must be changed to a supported locale.
3. Click **Record**. A visible timer indicates active recording. **Stop recording** finalizes both WAVs independently of any older transcription. **Transcribe after stopping** adds the saved recording to the transcription queue; turn it off for recording-only use. Missing inference files are reported before capture when automatic transcription is enabled.
4. Select a saved meeting in Active or Archived. Thread groups consecutive segments by source and assigned speaker identity, stopping at aligned pauses; unknown identities remain separate. Timeline shows each segment chronologically, including concurrent recognized streams. Unnamed headings show neutral Speaker N plus Me/Them audio source; named speakers show only their name in the transcript and Speakers panel. Audio-source metadata and playback routing remain unchanged; legacy transcripts retain their original Me/Them labels. Both views remain directly editable. Undo, Redo, Expand all / Collapse all and Thread | Timeline share the controls row. Switching views and visiting Settings preserve disclosure state; Copy includes the full corrected transcript.
5. Closing with an active recording, transcription or waiting queue asks for confirmation. **Keep open** leaves the work running; **Stop job and close** finalizes recording, cancels active transcription and discards waiting transcription requests before exit. Saved audio and prior transcripts remain available for later manual transcription. Idle launch, browsing history and opening settings never start audio capture.

Recording and transcription have independent lifecycles. You can start and stop the next conversation while an older one transcribes, browse history and open Settings. Finished recordings unrelated to an active or queued transcription remain available for playback, correction and review. The recording currently being transcribed and waiting recordings cannot be edited, reviewed, moved, trashed or queued again until their transcription work finishes.

Automatic transcription and the saved-recording **Transcribe** action share one first-in, first-out queue. Exactly one recording is transcribed at a time; waiting jobs show their queue position, and the status displays the active transcription alongside the recording timer. Each request retains the model/settings selected when it was queued. A failed job reports a recording-specific error and the next waiting job proceeds, without an automatic retry. The queue is in memory for this app session; it is not restored after exit. Saved recordings are never deleted when the queue is cleared.

Settings remains available during transcription. Its Remembered voices section refreshes in place when matching is toggled or a voice is forgotten; opening Settings does not cancel a running job. Settings changes apply to newly queued work, not requests already waiting.

The desktop loads the selected transcription model on its first job and keeps that one worker resident across both audio tracks and subsequent jobs. A later job with different model, runtime, language, thread or backend settings unloads the previous worker before loading its replacement. Each audio request starts fresh inference state; model weights remain loaded. Normal app exit closes and reaps the worker, including idle close. Linux parent-death protection kills the worker if its owning app dies, with a startup parent check to close the registration race. The worker-creating desktop thread remains alive between jobs because Linux ties this protection to that thread. Standalone CLI transcription remains one-shot.

Actual GTK/GPU smoke with the public JFK fixture verified two jobs on the same worker and clean exit for each engine. Force-killing the isolated GUI killed and reaped its Parakeet worker in 0.088s and its Nemotron worker in 0.171s; both disappeared from the GPU process list. No private recordings were used.

## Name and confirm speakers

Click either the speaker icon or name in a transcript heading to open that person's card in the **Speakers** left rail. The transcript remains beside it on wide windows; compact windows show the rail as a separate navigation pane. The header's arrow and **Back to Recordings** label form one native icon-and-label button, with matching tooltip and accessible name; activating either part restores the recording list. **Speakers** is a separate panel heading above the recording-scope explanation. Speaker cards have 12px interior padding on all sides, with 16px between snippets. **Rename all** opens an inline, prefilled name field with Apply/Cancel, not a dialog or turn menu. Names apply to an opaque identity in this recording; matching names never merge identities. Audio sources and timing stay unchanged.

The speaker icon/name in the transcript is the entry point. There is no separate Speakers toolbar shortcut.

The combined header control follows [GNOME HIG header-bar button guidance](https://developer.gnome.org/hig/patterns/containers/header-bars.html). Native smoke at 1080x824 and 420x824 verified a 169x34px Back target, readable panel heading, and actual navigation back to Recordings. Inspected captures: `/tmp/repeater-heading-1080.png` and `/tmp/repeater-heading-420.png` (temporary).

Expand a person's snippets to use **Right**, **Wrong** and **Show**. Right confirms only that snippet and is idempotent. Wrong removes confirmation and opens an inline correction form; choose a same-track existing identity or create a new person. Cancel leaves Wrong recorded. Reassignment affects only that snippet and needs a fresh Right. Show opens and scrolls to the transcript turn. Changes support persistent Undo/Redo.

After a newly confirmed snippet, the selected **Remember voice** modal offers enrollment from all currently confirmed snippets. **Not now** or Escape keeps confirmation, and another distinct confirmation can offer again. Repeating Right does not reopen the offer or undo confirmation. Remembered samples remain local and can be forgotten. Old saved unconfirm operations with a null speaker ID now reopen and save correctly.

## Correct and replay a transcript

Click a paragraph and type; there is no Edit mode. Both views share corrections, timestamps, immutable audio-source attribution and speaker identities. Short typing bursts form one Undo step. Corrections and complete-generation Undo/Redo history persist in private transcript-edits.json; JSON, TXT, SRT and history publish together. Save failures retain the draft and prevent leaving it behind or starting another job until saving succeeds. Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y work in the editors. Editing text removes stale current word alignment without erasing original generated alignment in correction/review history.

Each Thread turn and Timeline entry has a Play / Stop icon beside its speaker/time heading. Playback reads the matching Me (mic.wav) or Them (system.wav) source between the displayed bounds and stops at the end. Speaker identities never choose a different source file. A mixed source still contains other simultaneous voices: playback is not isolated-speaker audio separation. Fully aligned per-speaker streams split at pauses longer than one second using actual decoder times; incomplete alignment retains original text and coarse segment bounds rather than inventing times or dropping words. Only one excerpt plays at a time. Leaving the recording/view, opening Settings, starting a job, moving the recording or closing stops playback. Output uses the machine running the app; ssh -Y forwards the window, not sound.

**Retranscribe** warns before replacing manual corrections. Failed or cancelled inference preserves the previous corrected transcript. A successful replacement is itself undoable, so Undo restores the prior corrections. Human-entered text, including empty corrections or a literal `[BLANK_AUDIO]`, is preserved exactly.

## Review suspicious passages

Select a transcribed recording and click **Review transcript**. The app loads its saved review or asks the configured local model for listening candidates. Thread and Timeline underline suspect words inside the same editable paragraph and show a brief reason. **Done reviewing** returns to the normal transcript of that same recording, stops audio and preserves corrections, Undo/Redo, decisions and unresolved findings. Leaving during a scan cancels publication immediately; an in-flight HTTP call may continue until its 90-second timeout.

Play excerpt uses genuine decoder-derived word intervals and exact Unicode character spans with 180 ms context. Whole clip context plays the original segment. Neither model uses uniformly distributed or character-estimated word timing. Old or unaligned transcripts explicitly offer whole-clip playback. Alignment is approximate, not proof of hearing. Retranscription is explicit and can be undone together with the full previous generation, speaker registry and corrections.

**Keep** accepts the currently displayed text, including edits. **Commit edit** acknowledges changed text and is disabled when it matches the review input. **Skip** leaves the finding unresolved. Listening is optional for all decisions; there is no checkbox or playback gate. Direct typing still saves through the normal correction/Undo mechanism. Decisions store original ASR, review input, current accepted text, changed status, run/model/revision and date in private `transcript-review.json`. Separate playback events record start/stop/completion/failure, never verified hearing. Undo or further editing reopens a decision whose accepted text no longer matches, without deleting its history. Retranscription retires the active old findings but retains prior runs and decisions. **History** exposes all three histories; **Run review again** makes a new scan.

In **Settings → Transcript review**, enter a local OpenAI-compatible endpoint and model. Defaults are `http://127.0.0.1:8080/v1` and `gpt-4o`; `REPEATER_REVIEW_URL` and `REPEATER_REVIEW_MODEL` override defaults for settings files that omit these fields. On junkman, the existing LocalAI service is `http://10.97.87.40:8080/v1`; its `gpt-4o` alias is a local MiniCPM model, not an OpenAI cloud request. For example:

```bash
REPEATER_REVIEW_URL=http://10.97.87.40:8080/v1 make gui
```

The app does not start/download a model or fall back to a cloud provider. Review sends transcript text, not audio, only to explicitly configured loopback/private-network destinations. DNS addresses are checked and pinned; redirects and embedded credentials are refused. Exact, unambiguous source quotes and bounded model output are required. Invalid output, connection failure or a stale transcript leaves prior review history unchanged. Review failures use the same recording-scoped recovery card as other failures: preserved-progress guidance, **Retry review**, **Settings**, folder access and collapsed selectable/copyable **Technical details**. Retrying, completing or leaving review clears only the review failure; unrelated save/read/playback errors remain. Current bounds are 120 KB transcript text, 64 KB response and 40 findings.

The text-byte limit is not a model-context guarantee. Review submits the full transcript in one request and needs sufficient effective per-request capacity for instructions, transcript and the 4,096-token output allowance. On 2026-10-06, after explicit operator approval, the existing LocalAI `gpt-4o` alias was configured with `context_size: 32768` and `options: ["parallel:1"]`. A synthetic 40,017-token probe was rejected against exactly **32,768 available tokens**, confirming the effective window rather than just its YAML value. A full 511-segment synthetic transcript (55.36 minutes, 22,904 input tokens) then completed through the actual review/persistence path with HTTP 200, valid findings and `finish_reason: stop`; original transcript exports were unchanged. The largest saved transcript measured 15,655 input tokens, or 19,751 with the output allowance; its content was not reviewed or changed during verification.

Only that model's persistent `/models/gpt-4o.yaml` changed; global defaults, other model configurations and the Kubernetes deployment were not changed or restarted. The previous configuration is retained at `/models/.repeater-config-backups/gpt-4o.before-32k-20261006.yaml.bak`. This is one request slot, not 32K divided among four slots. Longer transcripts still need an adequately sized server; no model switch, silent text truncation or client batching is used.

The endpoint must support OpenAI-compatible **strict JSON-schema structured output** (`response_format.type: json_schema`). Generic JSON mode allowed MiniCPM to omit a finding's required reason on the long input; requesting the exact findings schema fixed that observed failure without weakening client-side quote, revision or history validation. Unsupported schema handling and malformed output remain recoverable failures, not empty successful reviews. The same 511-segment synthetic transcript then passed an actual native **Review transcript** button → asynchronous live-model request → saved inline finding → **Done reviewing** flow in an isolated 1080×876 window, returning to the same recording with original files unchanged. Post-verification GPU usage was 13,933 MiB of 32,607 MiB; this snapshot is not a peak-memory or concurrent-load guarantee.

These are candidates, not error ground truth: text-only review can miss mistakes or flag correct speech, including unfamiliar terms/numbers. Nothing is automatically rewritten or used to retrain ASR. Local-first review is the selected cost/deployment choice; online providers and opt-in training exports are not implemented.

## Manage recordings and recover errors

Use the selected recording’s **More** menu for **Archive / Restore** and **Move to Trash**; there are no row menus or permanent management buttons. Archive changes only its collection and keeps audio and exports in place. Trash names the recording in a confirmation with Cancel as the safe default. It moves the entire directory, including WAVs, exports and correction history, to the freedesktop Trash. The Undo action restores the original path, collection and selection without overwriting an existing destination. The OS/file manager can also restore or empty Trash; the application does not permanently purge it. A different-filesystem Trash is refused without changing the recording; use the file manager instead.

Errors belong to the affected recording. A persistent card states what failed, what remains saved and the useful recovery actions, with selectable/copyable **Technical details** collapsed by default. Failed or unfinished capture offers New recording and folder access, not an unusable Transcribe action. Transcription failure offers Retry transcription, inference settings and folder access. Retranscription failure keeps the previous corrected text, Copy and Undo available. Selecting another recording does not carry the previous recording’s error into it.

Closing a launch terminal (SIGHUP), Ctrl+C (SIGINT) or a normal termination request (SIGTERM) also shuts down owned jobs before exit; these signals do not leave a recording running without its window. A forced kill or machine crash cannot provide graceful finalization.

Recording, transcription and device scanning run off the GTK main thread; the app need not remain foreground. One recording/transcription job runs at a time. In wide windows, drag the divider to resize the recording rail; its default width is 360px so the Recordings header fits beside left-side window controls. Narrow windows retain native single-pane history navigation. Resizing between layouts preserves selection, recorder inputs and Settings. Settings starts directly with inference controls and shows job status/timer and **Stop recording** only when applicable; there is no idle Ready label. Stop and transcription completion do not eject Settings. The recorder has no setup-success label or duplicate Configure button; use the header gear.

Shortcuts: Ctrl+N opens the recorder, Ctrl+, opens inference settings, Ctrl+R refreshes history, and Ctrl+Q requests close. Preferences are stored atomically with mode 0600 at `${XDG_CONFIG_HOME:-$HOME/.config}/parrot/settings.json`; XDG_CONFIG_HOME must be absolute. Preferences contain local device names and inference settings, not credentials or transcripts. Errors appear in the window without deleting saved audio.

## Record explicitly with the CLI

```bash
make devices
make record ARGS="--title 'Example meeting' --duration 30 --transcribe --cpu"
# Or run directly; omit --duration to stop with Ctrl+C:
python3 linux/parrot.py record --title 'Example meeting'
```

`--microphone NAME` selects a microphone and `--system NAME` selects an output sink using the NAME column from `devices`. Omission uses the session's defaults. The system track captures the selected sink's monitor, including **all audio routed to that output**, not only a particular call or application. Device IDs are not persisted as unstable numeric graph IDs.

Microphone route validation follows active PipeWire links through existing processing nodes, including EasyEffects, back to the selected input. A direct hardware-to-recorder link is not required. Missing inputs, broken processing chains and a different microphone are rejected. The system track still requires a direct monitor link: an output used as an echo-cancellation reference must not be mistaken for playback capture.

Use headphones: this Linux path has **no acoustic echo cancellation**, so speakers can leak the other side into the microphone track. Obtain recording consent. There is no automatic call detection or silent capture. The CLI announces recording start, stop and the local session path. Ctrl+C is handled by capture to finalize the WAVs; a positive finite `--duration` provides an automatic stop.

Default sessions are outside the checkout, under `${XDG_DATA_HOME:-$HOME/.local/share}/parrot/meetings/UTC-UUID/`. XDG_DATA_HOME must be absolute. Newly created session directories are private (0700), and an existing destination is never reused. With `--output /absolute/path/to/new-session`, create the parent directory yourself first; a missing parent produces an actionable error. Keep explicit destinations outside version control and shared directories. Existing XDG parents retain their existing permissions.

Each successful session stores `session.json`, `mic.wav` (Me), and `system.wav` (Them). Both WAVs are mono 16 kHz signed 16-bit PCM. Capture aligns their arrival-time clocks with silence padding; this is not hardware-synchronized sample timing. The schema-version-1 manifest includes the session identity, title, start time, status, duration and track device/frame metadata. Failed sessions retain a failed manifest for diagnosis and are not accepted for transcription.

## Transcribe locally

```bash
python3 linux/parrot.py transcribe /absolute/path/to/session --profile multitalker-parakeet --cpu
make transcribe ARGS="/absolute/path/to/session --profile nemotron-3.5 --language en-US"
# Or append --transcribe to record to run inference after recording stops.
```

Shared options are --profile, --model, --runtime, --diarizer (Nemotron only), --language, --threads (positive integer, default 4), and --cpu. Omitted artifact paths use the selected profile's pinned defaults. Model selection is manual; no automatic speaker-count selection, model switching, cloud fallback or capacity-expanding external diarizer is used. With record --transcribe, inference paths and options are checked before capture. Path preflight cannot establish GPU readiness or model compatibility.

Without --cpu, inference requires the requested GPU backend to be active and rejects silent CPU fallback. Parakeet uses its explicitly built CUDA or Vulkan backend; Nemotron uses CUDA. CPU inference remains an explicit choice, not a fallback or a modest-hardware realtime guarantee.

Transcription runs each complete track independently, retains overlapping recognized voices and acoustic activity turns, then writes private transcript.json, transcript.txt, transcript.srt and transcript-edits.json. New transcript schema v2 includes a generation UUID/profile/language/backend/provenance, opaque source-scoped speaker UUIDs, neutral labels, acoustic speakerTurns and genuine optional words with exact Unicode spans. Same runtime speaker ordinals in mic/system never merge people across sources. IDs remain stable through edit/reopen/Undo/Redo within a generation; retranscription creates a new generation. Legacy schema v1 reads and exports unchanged, with no read-time migration. A failed/cancelled lane prevents publication of the entire replacement; original audio, manifest and prior corrections remain unchanged.

Recording and transcription do not upload audio or transcripts. Optional review sends transcript text, not audio, to the explicitly configured local endpoint; it has no cloud fallback or API-key integration. Raw recordings and correction/review histories are sensitive files; backups and access control remain the user's responsibility. make clean removes only .build/linux, not meeting data, and requires reinstalling inference artifacts.
